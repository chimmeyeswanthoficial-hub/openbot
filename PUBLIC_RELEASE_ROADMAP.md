## 3. Proposed release boundary — decide explicitly, do not quietly shrink the vision

The recommended **first** public scope remains self-hosted, single-organization,
human-supervised bounded QA/documentation work. Useful local planning/review features
can accompany that scope. This is a proposal, **not an approved change of requirements**.

A first release may keep unaccepted social, provider, computer, IDE and financial
features visibly disabled. If actual virtual PCs or external posting are included
in the chosen first-release promise, their gates become release blockers rather
than being relabeled optional after the fact.

A public multi-tenant hosted SaaS, consumer autonomous assistant, all-platform native
release, or unattended company operation is a broader product. Shared infrastructure
needs additional measured tenant isolation, authentication, abuse handling, privacy,
billing and operational acceptance. Public source availability is not SaaS readiness.
