## Rakazo: useful remaining material, not a second kernel

Prioritize routine occurrence/coalescing/backoff, cheap change fingerprints, review/blocked board
states and bounded ticket context. Later consider skill-lock/catalogue, pages, delegation, backups
and observability. Full mobile/desktop/voice/messaging/payment/computer/Prisma stacks are not the
next bottleneck. They bring separate terms, costs, authority and schema assumptions.

## OpenDots: useful review/recovery/scoping, not blanket execution permission

Use stored-request review, per-tool revocation/re-resolution, explicit interrupted states,
Space access checks and expected-revision editing as patterns. Do not copy blind interrupted
external-action retries, label-only read permissions or Promise timeout/AbortSignal as proof of
side-effect cancellation. `TaskActions.tsx` is task control UI, **not proof of a general
approve-before-save mechanism**. Pages tools can write authorized pages directly; extra human
review remains our enforcement responsibility.

No direct Rakazo/OpenDots runtime import was found in first-party runtime source in this review.
Their patterns informed design; it would be false to say all code/features have been consumed.
They need not ship inside a production image, but stay here as licensed, fingerprinted reference
and test material. Deletion or external archival needs a separate explicit decision.
